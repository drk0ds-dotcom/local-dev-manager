# Local Dev Manager

تطبيق سطح مكتب (Electron) لإدارة مشاريع Node.js المحلية من واجهة واحدة: تشغيل، إيقاف، إعادة تشغيل، ومراقبة مخرجات خوادم التطوير بدل فتح terminal لكل مشروع.

## التشغيل

```bash
npm install
npm start
```

أو شغّل `LocalDevManager.vbs` للتشغيل الصامت بدون نافذة أوامر (Windows).

## الميزات

- إضافة مشاريع Node (تحقق تلقائي من `package.json` ووجود سكريبت `dev` أو `start`)
- تعيين بورت حر تلقائيًا (يفحص سجل التطبيق والنظام فعليًا) مع إمكانية تعديله يدويًا
- اكتشاف البورت الفعلي من مخرجات السيرفر — زر "فتح" يستخدم البورت الحقيقي دائمًا
- كشف مدير الحزم تلقائيًا (npm / pnpm / yarn / bun) وكشف الإطار (Vite / Next / CRA / Angular) لتمرير البورت بالطريقة الصحيحة
- `install` تلقائي عند غياب `node_modules`
- كونسول لوقز ملوّن لكل مشروع (حد 500 سطر) مع مسح
- تشغيل تلقائي لمشاريع محددة عند إقلاع التطبيق
- فتح المشروع في VS Code أو في مستكشف الملفات
- اختصارات: `Ctrl+R` إعادة تشغيل · `Ctrl+O` فتح في المتصفح
- إيقاف كل العمليات الفرعية تلقائيًا عند إغلاق التطبيق
- يعمل على Windows وmacOS وLinux

## بنية المشروع

| الملف | الدور |
|---|---|
| `main.js` | العملية الرئيسية: النافذة، IPC، إدارة المشاريع والتخزين |
| `processManager.js` | تشغيل/إيقاف العمليات، كشف البورت والإطار ومدير الحزم |
| `preload.js` | جسر آمن (contextBridge) بين الواجهة والنواة |
| `index.html` | هيكل الواجهة والأنماط |
| `renderer.js` | منطق الواجهة وعرض اللوقز والحالة |

## التخزين

تُحفظ المشاريع في `projects.json` داخل مجلد بيانات التطبيق (`%APPDATA%/local-dev-manager` على Windows) — وليس في مجلد التثبيت، حتى يبقى الحفظ ممكنًا بعد التحزيم.

### تحسينات إضافية ضمن P0
- المثبّت (`npm install`) أصبح عملية متعقَّبة: إيقاف المشروع أثناء التثبيت يمنع انطلاق السيرفر بعدها (مجموعة `killedIds`).
- رسائل لوق أدق: "تم إيقاف المشروع" (متعمد) مقابل "توقف (exit code)" (مفاجئ).
- حذف مشروع متوقف لا يطبع تحذير "ليس قيد التشغيل".
- `windowsHide: true` على كل العمليات — لا نوافذ cmd وامضة.

### معنى "غير موقّع رقميًا" ولماذا يظهر تحذير SmartScreen

التوقيع الرقمي (Code Signing) ختم تشفيري يثبت أن المثبّت صُنع بواسطتك ولم يُعبث به. التطبيقات غير الموقّعة لا تسبب مشكلة تقنية، لكن Windows يعرض عند أول تشغيل تحذير **"Windows protected your PC"** وعلى المستخدم اختيار *More info → Run anyway*. التوقيع يشترى (شهادة OV/EV من جهة معتمدة مثل Sectigo/DigiCert — عادة 100–400$ سنويًا). عند توفرها:

```powershell
# PowerShell — التوقيع تلقائي أثناء البناء
$env:CSC_LINK = "C:\path\certificate.pfx"
$env:CSC_KEY_PASSWORD = "كلمة-المرور"
npm run dist
```

### النشر على GitHub والتفعيل الفعلي للتحديث التلقائي

1. أنشئ مستودعًا باسم `local-dev-manager` على GitHub وارفع الكود.
2. عدّل `package.json` → `build.publish[0].owner` إلى اسم مستخدمك.
3. أنشئ توكن بإذن `repo` وضع له متغير البيئة `GH_TOKEN`.
4. عند كل إصدار جديد: غيّر `version` ثم:

```bash
git tag v1.0.1
npm run dist          # يبني ويرفع تلقائيًا إلى Releases عند وجود tag
```

## 🔵 دفعة P3-F — فحص بورت بالاتصال الفعلي + إصلاحات مصاحبة (2026-09-27)

**البلاغ (من الاستخدام الفعلي):** المشروع الأول (Vite) يعرض `● خادمك` عند تشغيله، بينما المشروع الثاني (Node عادي على 127.0.0.1) ظل يعرض `✓ حر` رغم أن سيرفره يعمل على بورت 8575 — وتساءل المستخدم إن كان خللًا أم خطأ منه.

**التشخيص:** كان خللًا حقيقيًا بثلاثة أوجه:
1. فحص البورت كان بمحاولة **الربط** (listen) — وعلى Windows يمكن أن ينجح الربط زورًا بفضل `SO_REUSEADDR` عندما يستمع الخادم على `127.0.0.1` تحديدًا، فيُبلغ "حر" رغم وجود خادم. مشروع Vite كان يُكتشف لأنه يربط بطريقة مختلفة.
2. سيرفرات لا تطبع بورتًا بصيغة معروفة كانت تبقى عالقة في حالة "جارٍ الإقلاع" للأبد.
3. اكتُشف أثناء التحقيق خلل ثالث: مخرجات السيرفرات كانت تتجاوز `sendLog` وترسل للواجهة مباشرة — **ملفات اللوق على القرص بقيت 0 بايت** رغم عمل كل شيء.

| # | الإصلاح | التفصيل | الملفات |
|---|---|---|---|
| F1 | **فحص البورت بالاتصال الفعلي** | `isPortInUse` تحاول الآن `connect` فعليًا إلى `127.0.0.1` ثم `::1` بدل محاولة الربط — وجود مستمع حقيقي = مشغول، لا يمكن أن يفشل الكشف بسب طريقة ربط الخادم | processManager.js |
| F2 | **سيرفرات صامتة تُعتبر شغالة** | إذا بقي السيرفر حيًا 10 ثوانٍ دون طباعة بورت بصيغة معروفة → الحالة تنتقل إلى "يعمل" تلقائيًا (مؤقت `quietFallback` يُلغى عند الموت أو الخطأ) + نمط كشف جديد لـ `127.0.0.1:port` | processManager.js |
| F3 | **قناة لوق موحدة فعلًا** | `processManager` يمرر كل رسائله الآن عبر `emitLog` → `setLogSink(sendLog)` من main.js — مخرجات السيرفرات ورسائل التثبيت والإيقاف تُحفظ على القرص وتدخل السجل المستعاد بعد إعادة التشغيل (كانت تتجاوز الحفظ منذ P3-A) | processManager.js, main.js |
| F4 | **مؤشر يغطي حالة الإقلاع** | البورت مشغول + الحالة "يعمل" **أو "جارٍ الإقلاع"** = `● خادمك` (التشغيل لا يُسمح به أصلًا إلا على بورت حر — فالمشغول الآن هو خادمنا) | renderer.js |

### التحقق المنفذ لدفعة F

- `node --check` سليم للملفات الثلاثة المعدلة.
- اختبار حي فعلي يحاكي سيناريو البلاغ: خادم يستمع على `127.0.0.1:9377` فقط → `isPortInUse(9377) = true` ✅ وبورت حر `9378` → `false` ✅ (النسخة القديمة كانت ستفشل في كشف الأول).
- فحص `grep`: لم يبقَ أي إرسال لوق مباشر في processManager خارج القناة الموحدة.
- إعادة بناء المثبّت بالإصلاحات.
